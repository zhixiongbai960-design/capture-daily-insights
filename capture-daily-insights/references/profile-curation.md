# 画像整理标准

入口：[Skill](../SKILL.md)；回答收集见 [个人探索](personal-discovery.md)。

## 触发与范围

用户说“整理画像”“更新我的画像”或提出等价要求时，依据当前档案直接执行，不逐步等待重复确认。仅上传已填问卷时先保存原始回答，不默认同时生成画像。

先读档案 README、本地规则、现有画像及版本索引。已有专属画像标准时优先遵循其结构、窗口和路径；否则采用下述通用标准。只处理当前用户，不跨人合并，不把档案上传到公共仓库。

问卷不完整、没有六个月记录或从未生成过画像都不是硬门槛。只根据已有证据写作，明确材料覆盖与信息缺口，不为填满结构编造结论。

## 默认产出：两份当前画像

在 README 声明的画像目录（默认 `01_个人画像/`）维护两份文件，已有同类文件时沿用，不再造一组并行画像。

### 基础画像.md：现在是谁，如何与其协作

文件头标记版本号、整理日期、观察窗口及来源入口。正文结构：

1. 身份与已确认事实：必要经历、角色等，注明来源与时间；不强迫补齐隐私信息。
2. 当前主线与目标：方向、阶段优先级和角色定位。
3. 热爱：区分明确自述的兴趣与长期投入的行为迹象。
4. 擅长：区分本人自评、实践或结果支持、仍待验证的能力。
5. 价值观：分别写认同的原则、具体选择支持的证据及两者间的张力。
6. 思考与决策方式：纳入本人确认或跨时间反复出现的方式。
7. 工作、沟通与协作偏好：保存对后续协作有用且有依据的规则。
8. 当前状态：阶段重点、项目或合作判断，标记“截至 YYYY-MM-DD”。
9. 成长重点与待验证问题：保留为观察，不写成人格定论。

### 成长路径与深层画像.md：如何形成现在的特点

文件头同上，正文结构：

1. 人生关键事件主线：事件、当时的判断、选择和行动、结果及后续变化。
2. 持续热爱、反复展现的才能、跨阶段价值观：分别链接问卷和经历证据。
3. 四维横向综合：按下节问题比较，不只按年份罗列履历。
4. 观点、选择与行为的演化：起点、深化、转折及当前结论，保留当时语境。
5. 成长张力、Agent 待验证假设、反例与信息缺口。
6. 对未来协作或发展有帮助的综合判断：附来源和适用边界。

基础画像呈现当前有效摘要，成长画像解释形成过程。完整原话仍留在问卷、事件与觉察来源中，不用画像替代原始记录。

## 四维横向综合与近半年对照

基础材料指人生关键事件、热爱、擅长／才能、价值观四个维度；不要求必须有四份独立文件，组合问卷和访谈同样有效。

默认对照截至整理日向前滚动六个日历月内的觉察、事件补充及相关项目／决策记录。写明起止日期、实际覆盖与缺失材料。历史问卷和更早的关键事件仍可用于人生主线，但不混入近半年统计；不要延长窗口来凑证据。日历月份回推遇无对应日时取目标月最后一天。

必须总结并回答：

- 人生关键事件呈现什么主线与转折？用“发生什么—如何选择和行动—带来什么变化”解释。
- 哪些热爱持续出现，哪些只是阶段兴趣？
- 哪些才能在不同场景反复展现，有哪些作品、行动、结果或他人反馈支持？
- 哪些价值观在不同人生阶段出现？认同和践行是否一致，优先级是否变化？
- 哪些兴趣和才能总是绑在一起出现？列出同一情境的投入和行动证据。
- 哪些价值观驱动了对这些兴趣与才能的选择、坚持、拒绝或改变？区分本人明确动因和 Agent 推断。
- 兴趣、才能与价值观之间是否存在可验证的隐藏模式？用具体情境、行动方式和取舍描述“这个人”，不套空泛标签或人格诊断。

形成综合叙述前用证据清单核对，必要时使用表格：

| 暂定模式 | 兴趣／投入证据 | 才能／行动证据 | 价值观／取舍证据 | 来源与日期 | 反例、边界与可信程度 |
| --- | --- | --- | --- | --- | --- |

不要求凑出一个统一模式。证据不足则写待验证；有变化则保留变化，不为“贯穿始终”的叙事抹平冲突。

## 证据准入与冲突

画像中明确区分：

- 已确认事实：本人明确提供，或原始材料、结果支持。
- 本人自述：兴趣、自我评价、原则、偏好，附语境和日期。
- 行为验证：具体行动、持续表现或结果，附对应来源。
- Agent 分析／待验证：跨记录归纳或假设，注明不是本人原话。
- 当前状态：阶段性信息，注明截至日期。

不能把喜欢当擅长、认同当践行、表达当行动、暂时情绪当稳定人格。稳定结论应有跨时间／场景证据、行动结果，或本人明确确认是长期特点；一次分析不升级为确定事实。

旧画像是比较基准，不是新结论的唯一证据。回查原始回答与记录，防止画像自我佐证。未采纳的外部观点和 Agent 建议不归为本人观点或承诺。

本人较新的明确更正优先用于当前画像；代表认知变化的内容保留演化轨迹。重要冲突写明并请求澄清，可先以待确认项继续；不静默重写历史原话，不替本人评判。

## 情境与假设验证

### 核对证据独立性与情境

- 同一事件的重复讲述、转写与摘要是同一事件的不同来源，不能按多次独立行为计算；多个 Agent 对同份材料的分析也不是新增证据。
- 用户认可某个解释，只能按本人认同或自述记录，不自动成为行为验证。思想实验、假设回答不是实际选择；有真实事件支持时再分别链接。
- 按需核对当时的角色与决策权、资源和期限、关系压力、可选方案及可逆性。不同条件可能解释不同选择，不能把环境约束直接写成稳定特点。缺失条件注明未知，不编造。
- 可信程度说明依据、反例与覆盖限制，不用模型自评百分比或固定记录数量代替证据判断；原始素材不等待画像结论成熟才保存。

### 待验证假设的闭环

只跟踪对自我理解或当前选择有帮助的假设，不为每条记录强建一条。优先在现有成长画像的“待验证假设／信息缺口”中维护；探索阶段尚未要求整理画像的内容仍留在访谈进度，不另建平行画像库。

每个需要跟踪的假设保留：

- 暂定判断：明确是 Agent 解释，不冒充用户原话。
- 支持证据：事件日期、来源链接和证据类别。
- 反例与其他解释：已有反例、可能的替代解释；未找到反例不等于不存在。
- 适用情境：哪些条件下出现，哪些条件尚不清楚。
- 待核对问题或自愿观察：什么新信息可能支持、修正或否定判断；行为观察是建议，不自动成为用户承诺。
- 状态与变更：待验证／证据较充分／已修正／已搁置，注明更新日期、用户反馈、新证据与改变原因。状态不代表永久定论，“证据较充分”也须注明是自述还是行为支持。

每次整理画像时回看相关假设，依据新材料修正或保留待验证；不要为了完成闭环强行升级状态。用户可以查看、更正、否定、跳过或停止，拒答、不同意和缺少后续反馈不视为假设成立；不能用“缺乏自知”等解释推翻用户的否定。
原话和旧版本不改写。发现有价值的缺口时可邀请[定向追问](personal-discovery.md)，不自动启动访谈，也不因待验证问题阻塞本次画像整理。

## 执行流程

1. 确认档案范围与规则，读取当前画像、画像索引及版本索引。
2. 完整阅读相关基础回答及事件资料；整理日期、近半年起止与实际覆盖情况。
3. 从相关索引检索近半年记录，完整阅读拟引用材料；有歧义时回查原始附件。
4. 形成结论—证据清单：日期、类别、独立事件或行动结果、关键情境、反例、当前有效性。标出问卷与记录的呼应、补充、偏离和变化。
5. 按四维问题完成分析，分开稳定特点、当前状态、推断与缺口；按上述闭环回看相关待验证假设，保留替代解释和适用条件。
6. 更新两份当前画像，注明来源及相对上版变化；无证据支撑的部分不强行填满。
7. 如有实质内容变化，保存完整版本并更新索引；无语义变化不重复建版。
8. 更新画像索引与档案已有日志，检查相对链接和导航可达性；有 Python 时运行档案检查脚本。快照来源链接需按新位置修正。
9. 简短反馈新增、修改、保持不变的核心结论、四维模式、关键未知项，附当前画像和新版本链接。

## 完整版本留存

沿用既有版本机制；没有时在画像目录下创建 `版本历史/INDEX.md`，永久编号从 `P001` 递增，不复用。

- 两份当前画像已有内容但无版本机制时，先存 `P001` 基线，再将实质更新存下一版；首次建立画像时以首份实际画像为 `P001`，不创建空基线。
- 每版保存两份完整快照：`Pnnn_YYYY-MM-DD_基础画像.md`、`Pnnn_YYYY-MM-DD_成长路径与深层画像.md`。同日多次实质更新也用不同编号。
- 快照注明版本号、保存日期和“此为当时画像快照”，保存完整内容，不以差异摘要代替；源链接保持有效。
- 版本索引每版登记编号、日期、两份快照链接、相对上版的增补／改写／失效结论及证据依据。
- 历史版本只追加，不覆盖、不删除；当前主文档可更新。历史快照不是当前事实来源。
- 仅导航或格式修正且没有含义变化时不新增版本；报告已检查但无实质更新的原因。

用户无需自己命名、编号或维护版本。新增画像、版本索引及快照都必须从档案索引链路可访问；完整档案导出后相对链接仍能使用。
